For the Call Center team8 November 2026 · Yurii Tsykvas

One text. One segment. And we finally know it was opened.

Every text we send with a link to a quote, e-sign or payment page costs two SMS segments instead of one — the link alone is 80–150 characters. A short branded link brings the message back to one segment, looks like it comes from us, and tells us whether the customer tapped it.

What we ruled out, and why

Prices and limits read from the vendors' pages on 8 November 2026. Public shorteners such as bit.ly or tinyurl are rejected by US carriers outright, so a branded domain is required whichever option you choose.

Twilio Link Shortening

Built into our SMS provider, but priced at $0.015 per message — more than the segment it saves. At 600,000 messages a month that is about $9,000 a month. Works only inside Twilio (not email), links expire after a fixed 90 days, no revocation.

Bitly

Self-serve plans stop at 3,000 links a month; everything we need is "contact sales"; links can never be deleted or disabled.

Short.io

The one subscription that fits — kept as the "use an existing product" option above. Enterprise plan, $148 a month.

Self-hosted open source (Shlink)

A separate PHP service for a Rails team, an open critical security advisory with no fixed version listed, no batch API. Saves a day or two of code, costs a service to run forever.

How it works

When the messaging system prepares a text, it swaps each long link for a short one. The customer taps the short link and lands on the original page; we record that a person opened it, and when. If anything goes wrong on our side, the text goes out with the long link — sending is never blocked.

  1. The messaging system renders the template.
  2. The shortener turns each long link into a short one on our domain.
  3. The text goes out — one segment.
  4. The customer taps; our redirect opens the original page (quote, e-sign, payment).
  5. We record that a person opened it, when, and how many times.

After 90 days, or sooner if we revoke it, the short link shows a plain "this link has expired, call us" page instead of an error.

What it costs to keep running

The module lives inside the application we already run and uses the database, background jobs, monitoring and feature flags we already pay for. At 1,000–20,000 links a day it is about a quarter of a request per second — far below anything that would need new capacity.

How we will know it worked

A two-week pilot on one or two SMS templates, switched on by a feature flag — a switch we flip without a release — and compared with the rest. It can be switched off within a minute; links already sent keep working.

Segments and dollars per message

Pilot templates at about 1 segment versus about 2 for the rest — visible from the first day.

Share of links opened by a person

Measured for the first time ever. A strong signal, not legal proof of delivery.

Undelivered rate

Watched daily. If carriers start filtering the new domain, we switch off the same day and re-register under a new one.

Defaults we will build with

  • If the shortener fails, the message goes out with the long link. A delivered message matters more than a saved segment; we get an alert.
  • Email is shortened too, switched on after the SMS pilot, with the email provider's own click tracking turned off for our links — one record of opens across SMS and email.
  • Links live 90 days by default; shorter lifetimes per template can be set when needed.
  • We record whether a person opened the link, when, and how many times — nothing else. No IP addresses, devices or locations; automated previews are filtered out; click events are kept 13 months, the destination is erased 7 days after the link expires.
  • We only shorten links to our own pages. Anything else stays long — the domain cannot be used to disguise someone else's site.
